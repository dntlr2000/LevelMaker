# 수동 스테이지 제작

Unity 6000.5 이상에서 `Tools > Rogue Dungeon Lab > 스테이지 직접 설계`를 엽니다. 이 도구는 기존 **다층 FPS 아레나 모델**을 사용합니다. 단층 로그라이크의 DungeonBlueprint, Stage Override, Bake, RunState는 별도 경로이며 변경하지 않았습니다.

## 처음 만드는 순서

1. **새 스테이지 설정**에서 가로·세로 8–64셀, 1–4층, 셀 크기 2–5m와 층간 높이 3–6m를 정하고 **이 설정으로 새 빈 스테이지**를 누릅니다. 기본값은 16×16셀·1층·셀 3m·층간 4m입니다. 프로젝트의 `.asset` 위치를 선택하면 바닥과 시작 스폰만 있고 외곽벽은 없는 v2 자산이 생깁니다.
2. **바닥 칠하기 / 바닥 지우기**를 선택하고 드래그해 형태를 만듭니다. **벽 그리기**는 셀의 상·하·좌·우 경계 가까이를 클릭하거나 드래그합니다. **벽 자동 배치 (전체 층)**는 모든 층의 외곽과 내부 구멍에서 비어 있는 경계만 채웁니다. 기존 벽의 ID·규격은 유지하고 계단 개구부·착지 통로는 제외합니다. **문 뚫기** 또는 벽 선택 후 삭제로 원하는 구간을 엽니다.
3. 두 층 이상이면 아래층에서 **계단 배치**를 선택합니다. 상승 방향과 위치를 정하면 폭 2셀·길이 4셀 계단과 개구부가 생깁니다. 앞뒤 착지 바닥을 남겨야 합니다. 계단을 선택해 삭제하면 양층의 계단 공간 바닥이 복원됩니다.
4. **시작 스폰**으로 시작 지점을 지정합니다. **콘텐츠 배치**에서 구조물·엄폐, 적, 기믹, 아이템과 콘텐츠를 고르고 빈 바닥을 클릭합니다.
5. **선택·이동**으로 콘텐츠를 드래그합니다. 선택 속성에서 셀 좌표·층·점유 크기·실제 크기·회전·콘텐츠를 바꿉니다. `Delete` 또는 삭제 도구로 지우고, `Ctrl+Z`/Redo 또는 창의 취소/다시 실행 버튼으로 되돌립니다. 한 번의 칠하기 드래그는 한 Undo 작업입니다.
6. **저장**으로 자산을 저장합니다. 중간 초안도 저장할 수 있습니다. 겹침·없는 바닥·잘못된 계단·누락 프리팹 등의 필수 오류는 빨간색으로 표시되며 장면 적용을 차단합니다. 시작 스폰에서 닿지 않는 구역이나 연결하지 않은 층은 노란색 **연결성 경고**만 표시하므로, 의도한 격리 구역이면 그대로 적용할 수 있습니다.
7. **검사 후 장면에 적용**을 누릅니다. 생성기가 비어 있으면 현재 장면에 하나를 추가합니다. 이후 같은 생성기에 적용하면 생성 루트 하나를 교체합니다. **테스트 플레이어 연결** 후 Unity의 Play로 확인합니다. 클릭해 시점을 잠그고 WASD 이동, Space 점프, R 시작 복귀, Esc 잠금 해제를 사용합니다.
8. 장면은 `Ctrl+S`로 저장합니다. 수동 자산을 더블클릭하면 편집기를 다시 엽니다. Play 중에는 수동 자산 편집이 잠기며, 종료 후 계속 편집할 수 있습니다.

저장 단위는 `FpsArenaStageAsset`입니다. Hierarchy의 생성 자식 오브젝트를 직접 옮긴 결과는 저장 원본이 아닙니다. 자산 수정 후에는 다시 **장면에 적용**해야 표시가 갱신됩니다. 미리보기 장면은 마지막 적용 데이터도 보존하므로 자산만 수정한 상태에서 domain reload가 발생해도 기존 장면과 레이아웃이 일치합니다.

연결성 경고는 첫 번째 시작 스폰과 바닥 셀·구획벽·고정 구조물·계단 링크를 사용하는 격자 검사 결과입니다. 점프·낙하·동적 문·텔레포트 등 실제 게임의 이동 수단까지 판단하지 않습니다. 수동 자산은 연결성 경고가 있어도 장면 적용·Play 로드가 가능하며, 별도 승인이나 경고 해제 설정은 필요하지 않습니다. 기존 절차 생성 모드의 전체 연결성 검사는 계속 필수입니다.

## 현재 맵의 규격 변경 (0.17.0)

- 왼쪽 **현재 스테이지 규격**에서 가로·세로·층 수·셀 크기·층간 높이를 입력합니다. 층간 높이는 전 층 공통이며 바닥 두께/계단 규격은 이번 UI의 편집 대상이 아닙니다.
- 변경 전후 실제 가로·세로 미터 크기와 추가될 바닥 셀 수를 확인한 뒤 **규격 변경 적용**을 누릅니다. **규격 입력 취소**는 입력만 되돌립니다. 적용은 한 번의 Undo/Redo이며 자동 저장하거나 장면을 갱신하지 않습니다.
- 확대는 기존 범위 밖에 바닥만 추가합니다. 기존 범위 안의 구멍·계단 개구부·벽·콘텐츠는 그대로 두고, 추가 층에도 계단/외곽벽을 만들지 않습니다. 필요한 경계는 **벽 자동 배치**로 직접 채우세요. 과거 외곽벽이 내부 경계가 되어도 자동 삭제/이동하지 않습니다.
- 축소는 바닥을 포함한 기존 데이터가 새 범위 밖에 남으면 보류합니다. 문제 목록의 층·좌표·ID를 보고 먼저 바닥 지우기/배치 이동·삭제로 정리하세요. 여러 오류는 **나머지 문제도 모두 표시**로 확인합니다. 서쪽·남쪽 벽의 음수 기준 좌표 자체는 정상입니다.
- 기존 벽과 콘텐츠의 미터 치수, ID·셀 좌표는 자동 변경하지 않습니다. 셀을 줄여 오브젝트가 점유 공간을 넘거나 층간 높이를 줄여 벽/오브젝트가 너무 높아지면 해당 치수부터 수정하세요. 월드 위치는 기존 중심 기준 계산식으로 재계산되므로 가로·세로·셀 크기 변경 시 위치도 바뀔 수 있습니다.
- 카탈로그 연결 여부와 전체 연결성 경고는 기존 검사를 유지합니다. 자산의 **저장**과 **검사 후 장면에 적용**을 각각 실행하세요. Play 중에는 편집할 수 없습니다.

## 벽 높이·두께와 배치 기본값 (0.17.0)

- **선택·이동**으로 벽을 고르면 길이(셀/m), 높이(m), 두께(m)가 표시됩니다. 값을 입력하고 **선택한 벽에 적용**을 누릅니다. 길이는 기존 벽 그리기/문 뚫기/삭제로 조절하며, 이전 벽 조각의 문 시작·폭 편집도 유지합니다.
- 높이는 0.1m–층간 높이−0.1m, 두께는 0.1–1m입니다. 잘못된 입력은 자동 보정하지 않고 원인을 표시합니다.
- **벽 치수 일괄 편집**에서 전체/내부벽/외곽벽·구멍 경계를 고르고 치수를 입력합니다. 대상 개수를 확인해 **현재 층 벽에 일괄 적용** 또는 **전체 층 벽에 일괄 적용**을 선택합니다. 확인 대화상자에서 취소하면 변경하지 않습니다. ID·길이·문을 보존하고 한 번의 Undo로 복원합니다. 이전 벽 조각은 내부벽에 포함합니다.
- **벽 배치 기본값**은 스테이지별로 저장합니다. 내부 높이는 처음에 **층간 높이−0.25m 자동**, 내부 두께는 0.25m, 외곽 높이/두께는 1.5m/0.15m입니다. 자동을 끄면 내부 높이를 직접 지정할 수 있습니다.
- **벽 배치 기본값 저장**은 제작 기본값을 자산에 반영합니다. 영구 보관하려면 상단 **저장**도 누르세요. 기본값은 앞으로 그리는 벽과 자동 배치가 추가하는 빈 외곽에만 적용되며 기존 벽은 바뀌지 않습니다. 기본값만 바꾸면 배치 해시도 바뀌지 않습니다.
- 기존 자산은 열기만 해서는 기본값을 덧쓰거나 저장하지 않습니다. **다른 이름으로 저장**은 기본값도 복사합니다. 변경한 치수는 자산 저장/재로드 후 유지하며 장면은 별도 적용합니다.

## 편집 가능한 외곽벽과 구형 자산

- 외곽벽은 내부벽과 같은 `partitions` 데이터에 저장됩니다. 외곽/구멍의 기본 벽은 높이 1.5m·두께 0.15m이며 기존 색상과 Collider를 보존합니다. 내부벽 기본 치수는 기존대로 유지합니다.
- 삭제한 벽은 장면 적용·저장·재로드·Play로 다시 생기지 않습니다. **벽 자동 배치**를 명시적으로 다시 누르면 삭제했던 빈 경계도 채워집니다. 반복 실행은 중복 생성하지 않으며 전체 작업은 하나의 Undo입니다.
- 구형 v1 자산은 런타임에서 원본을 수정하지 않고 기존 외곽 가드를 명시적 벽으로 복원합니다. 격자 편집 전 **편집형 벽으로 변환 (Undo 가능)**을 누르세요. 자동 덮어쓰기·자동 저장은 없으며 변환 후 수동 배치 해시가 v2로 바뀔 수 있습니다.
- 절차 생성은 기존 외곽을 그대로 만들고 기존 시드·내부 배치·해시를 유지합니다. 개별 외곽을 열려면 아래 생성 결과 복사로 수동 자산을 만든 뒤 편집합니다. 계단 난간 자체 편집은 이번 기능에 포함하지 않습니다.

## 생성 결과에서 시작

기존 FPS 아레나를 생성한 뒤 위쪽 **생성 결과 가져오기** 칸에 생성기를 넣거나 **선택 연결**을 누릅니다. **새 수동 자산으로 복사**는 기존 설정·원본·장면을 바꾸지 않고 바닥, 스폰, 계단, 벽, 콘텐츠를 복사합니다. 방 구획벽은 개별 편집 가능한 경계 구간으로 저장됩니다. 절차 생성 당시의 방 번호·요청 밀도·시드 보고서는 수동 맵의 입력이 아닙니다.

이전 벽 조각 모드의 벽을 선택하면 문 시작 셀과 폭도 바꿀 수 있습니다. 수동 스테이지에서 시드를 바꿔도 배치는 그대로입니다. 생성기의 **수동 스테이지**를 비우면 기존 절차 생성으로 돌아갑니다.

## 다른 프로젝트의 콘텐츠로 교체

UPM 배포는 `UpmPackages`의 **Core 0.17.0 + Lab 0.17.0**을 함께 적용합니다. Runtime에는 Core만 필요하며, Lab는 편집기와 테스트 플레이어를 제공합니다. `R9.1 UPM 패키지 동기화`는 수동 제작 코드를 포함합니다. 기존 `.unitypackage`의 Runtime Core + Lab Sample 내보내기에도 수동 편집기를 포함합니다. 스테이지 `.asset`, 사용 카탈로그와 그 프리팹·재질 의존성은 함께 전달해야 합니다.

- 편집기의 **프로젝트 프리팹 등록·교체**를 펼치고 카탈로그를 만들거나 연결합니다.
- 범주와 고유 키(예: `enemy.guard`, `gimmick.door`, `cover.crate`)를 정하고 호스트 프로젝트의 Prefab을 등록합니다. Renderer/Collider Bounds는 자동 측정합니다. 상세 Inspector에서 점유 크기·높이·Bounds를 조정할 수 있습니다.
- 기존 키에 새 프리팹을 등록하면 다음 장면 적용에서 그 키를 사용하는 배치가 모두 바뀝니다. 원본 프리팹의 AI·상호작용 스크립트는 유지합니다.
- 프로젝트별 카탈로그를 따로 만들고 생성기의 **호스트 카탈로그 교체**에 연결하면 스테이지 자산과 논리 배치를 그대로 둔 채 콘텐츠를 교체합니다. 같은 키·범주를 유지해야 합니다. 누락된 키나 범주 불일치는 기존 장면을 지우기 전에 차단합니다.
- 필요하면 프리팹 컴포넌트에서 기존 `IFpsArenaContentInitializer.InitializeArenaContent(FpsArenaSpawnContext)`를 구현합니다. 생성 루트가 비활성 상태인 동안 stable ID, 셀, 크기와 Layout을 받아 호스트 게임 시스템에 연결할 수 있습니다.

```csharp
generator.manualStage = authoredStage;
generator.manualCatalogOverride = projectCatalog;
generator.Generate();
```

프리팹은 저장된 점유 공간 안에 비율을 보존하여 맞춰집니다. 더 큰 모델을 원하면 해당 배치의 점유/실제 크기를 변경하세요. 구조물·엄폐의 점유 셀은 통로 검사에서 막힌 셀로 취급합니다. 적·기믹·아이템의 실제 행동, 동적 문, NavMesh와 전투/픽업 시스템은 호스트 프로젝트가 담당합니다. 벽·바닥·계단은 기본 생성 기하이며, 이번 카탈로그 교체 대상은 배치 콘텐츠입니다. 수동 FPS 자산은 단층 DungeonBlueprint Bake/RunState와 직접 호환되지 않습니다.

## 규격·벽 UI 보완 검증 (2026-11-06)

- Unity 6000.5.3f1에서 전용 EditMode 26/26, 전체 EditMode **214/214**, 전체 PlayMode **23/23** 통과. 규격 확대/안전한 축소/실패 보존, 미터 치수·ID 보존, 개별/일괄 벽 편집과 필터, 제작 기본값의 해시/파일 비변경, Undo/Redo, 재임포트 및 적용 스냅샷의 실제 Collider 치수를 포함합니다.
- 기존 절차 생성 72개 조합의 해시/논리 배치/외곽 Collider가 변경 전 기준선과 일치했습니다. 개발 Assets 없는 Core-only/Core+Lab 0.17.0 소비 프로젝트에서도 패키지 단독 컴파일·규격 API·벽 치수·적용 결과 복원을 확인했습니다.
